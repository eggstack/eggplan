# Architecture Decision Records

ADRs record durable Eggplan architecture decisions that materially constrain
multiple milestones.

Accepted ADRs are historical decisions. Do not silently rewrite their decision
or rationale after dependent work lands. If the architecture changes, add a
new ADR that supersedes the old one and update affected roadmaps/registry.

Naming: ADR-NNNN-short-title.md

Each ADR should contain status, context, decision drivers, considered options,
decision, consequences, compatibility/migration, security/reliability
implications, verification expectations, and supersession.
